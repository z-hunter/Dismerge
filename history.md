# История версий Dismerge (current version = 0.0.9)

## v0.0.9 - Система спрайтов для фишек и исправление Z-координат

### 🎮 **Новая функциональность**
- **Кастомные спрайты для фишек**: Каждая эволюционная цепочка может иметь собственный атлас со спрайтами
- **Автоматическое определение типа фишки**: Система автоматически определяет, есть ли у фишки уникальный спрайт
- **Умное отображение подписей**: Подписи уровней показываются только для фишек без уникальных спрайтов
- **Цветовая дифференциация**: Первые 6 эволюционных цепочек получают уникальные цвета для подписей

### 🔧 **Технические изменения**
- **Новая архитектура визуализации**: Переработана система отображения фишек с поддержкой кастомных спрайтов
- **Флаг `has_custom_sprite`**: Каждая фишка знает, есть ли у неё уникальный спрайт
- **Упрощенная логика цветов**: Убрана сложная логика проверки атласов, цвета назначаются по порядку
- **Оптимизированная функция `update_level_visual`**: Теперь работает только для фишек без уникальных спрайтов

### 🎨 **Система спрайтов**
- **Формат атласов**: `{evo_id}.atlas` (например, `GEN_P.atlas`)
- **Формат спрайтов**: `{evo_id}-{level}` (например, `GEN_P-1`, `GEN_P-2`)
- **Автоматическое переключение**: При получении сообщения `set_sprite` фишка автоматически скрывает подпись уровня
- **Fallback на дефолтный спрайт**: Если спрайт не найден, используется стандартный токен с подписью

### 📋 **API для спрайтов**
```lua
-- Установка кастомного спрайта
msg.post(token_id, "set_sprite", {
    atlas_id = "GEN_P",
    sprite_name = "GEN_P-1"
})

-- Автоматическое управление подписями
-- Если has_custom_sprite = true: подпись скрыта
-- Если has_custom_sprite = false: показывается подпись с цветом
```

### 🎯 **Логика отображения**
- **Фишки с уникальными спрайтами**: Подпись уровня заменяется на пробел, спрайт переключается на кастомный
- **Фишки без уникальных спрайтов**: Показывается подпись уровня с цветом из палитры (красный, зеленый, синий, желтый, пурпурный, голубой)
- **Автоматическое определение**: Система сама определяет тип фишки при инициализации

### 🔧 **Рефакторинг кода**
- **Упрощение `evolution_tables.lua`**: Убрана сложная логика проверки атласов, упрощена функция `get_chain_color`
- **Оптимизация `token.script`**: Убраны избыточные проверки и логирование, добавлен флаг `has_custom_sprite`
- **Централизованное логирование**: Использование `debug_logger` вместо `print()` в `evolution_tables.lua`

### 📊 **Цветовая палитра**
```lua
local colors = {
    vmath.vector4(1, 0, 0, 1),    -- Красный (1-я цепочка)
    vmath.vector4(0, 1, 0, 1),    -- Зеленый (2-я цепочка)
    vmath.vector4(0, 0, 1, 1),    -- Синий (3-я цепочка)
```

### 🐛 **Исправленные баги**

- **Фишки, созданные мерджем, не отображались**: Фишки, созданные при слиянии, теперь корректно отображаются поверх ячеек поля

### 🔧 **Технические изменения Z-координат**

- **Исправление `factory.create`**: Восстановлен параметр Z=1 в `factory.create` для фишек
- **Правильная иерархия слоев**:
  - **Ячейки поля**: `final Z = -0.5` (pos.z=-0.5 + factory Z=0)
  - **Фишки на поле**: `final Z = 1` (pos.z=0 + token.go Z=0 + factory Z=1)
  - **Иконки генераторов**: `final Z = 0.1` (pos.z=0.1 + factory Z=0)
  - **Перетаскиваемые фишки**: `final Z = 1.5` (pos.z=0.5 + token.go Z=0 + factory Z=1)

## v0.0.5
### 🐛 Исправленные баги
- **Механика выделения клеток**: Исправлена система выделения клеток поля, которая не работала корректно

#### Суть проблемы
Механика выделения клеток имела несколько критических проблем:
1. **Неправильные пути к объектам**: Ячейки отправляли сообщения на несуществующий объект board
2. **Потеря выделения при перетаскивании**: Выделение не сохранялось и не восстанавливалось после операций с фишками
3. **Неправильная обработка состояний**: Логика восстановления выделения работала некорректно

#### Решение
**Исправление путей к объектам:**
- Изменен путь в `item_script.script`: `msg.post("/board", ...)` → `msg.post("main:/board_factorys#board", ...)`
- Исправлен путь в `debugger.lua` для отладочных сообщений

**Улучшение логики выделения:**
- Добавлено поле `pre_drag_selection` для сохранения состояния выделения перед перетаскиванием
- Исправлена функция `start_drag()` - теперь создается копия объекта выделения
- Улучшена функция `perform_move()` - выделение перемещается вместе с фишкой
- Исправлена функция `perform_merge()` - выделение переходит на новую фишку после мерджа
- Улучшена функция `perform_return()` - выделение восстанавливается при возврате фишки
- Добавлена функция `check_selection_after_drag()` для проверки состояния выделения после операций

**Добавлена отладочная информация:**
- Подробное логирование всех операций с выделением
- Отслеживание ID объектов при отправке сообщений
- Диагностика координат и расстояний в функции `find_cell_at_position`

#### Результат
Теперь механика выделения работает корректно:
- ✅ Выделение сохраняется при начале перетаскивания
- ✅ Выделение перемещается вместе с фишкой при перемещении
- ✅ Выделение переходит на новую фишку при мердже
- ✅ Выделение восстанавливается при возврате фишки на исходную позицию
- ✅ Сообщения между объектами работают корректно

### 📋 Технические детали
```lua
-- Сохранение выделения перед перетаскиванием
if self.selected_cell then
    self.pre_drag_selection = { x = self.selected_cell.x, y = self.selected_cell.y }
end

-- Восстановление выделения при возврате
if self.pre_drag_selection and 
   self.pre_drag_selection.x == self.dragged_from.x and 
   self.pre_drag_selection.y == self.dragged_from.y then
    select_cell(self, self.dragged_from.x, self.dragged_from.y)
end

-- Перемещение выделения вместе с фишкой
if self.pre_drag_selection and 
   self.pre_drag_selection.x == self.dragged_from.x and 
   self.pre_drag_selection.y == self.dragged_from.y then
    select_cell(self, target_cell.x, target_cell.y)
end
```
